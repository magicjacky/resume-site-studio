# 简历网站工坊

根据用户提供的真实简历、履历、项目资料和目标岗位，制作内容可信、可以继续编辑、适合电脑和手机浏览的个人网站。需要求职匹配分析时，先调用内置的职位匹配证据分析器，再决定网站重点。

## 适合什么时候使用

- 把 Word、PDF、Markdown 或文字简历做成个人网站。
- 制作求职主页、职业介绍页、个人作品集或学术主页。
- 根据招聘要求分析匹配度、硬性门槛和能力缺口。
- 为已有简历网站更换风格、补充案例或增加适度动态效果。

## 你会得到什么

- 一份基于真实材料整理的个人信息与经历结构。
- 一个可在本地打开的响应式网站，包含 HTML、CSS 和必要的 JavaScript。
- 清晰的首页定位、经历、项目、能力、教育背景和联系方式。
- 桌面端、手机端、打印版和“减少动态效果”模式的检查结果。
- 如提供目标岗位，额外获得一份职位要求与个人证据对应表。

## 工作流程

1. **整理资料**：读取用户提供的简历、项目材料、链接、图片和目标岗位，不要求用户重新整理格式。
2. **核对事实**：区分原始事实、合理概括和待确认信息，不虚构公司、学历、日期、证书、客户评价或项目数据。
3. **分析岗位**：如果用户提供招聘要求，读取并执行 `modules/job-fit-evidence-analyzer/SKILL.md`，先完成职位匹配分析。
4. **确定重点**：根据求职、个人介绍、作品集或学术展示目的，选择首页重点和内容顺序。
5. **设计网站**：默认提供专业简洁或具有适度动态效果的表达方式；用户给出参考风格时，以参考风格为准。
6. **生成文件**：输出可编辑的静态网站，公开目录至少包含 `index.html`、样式文件以及必要脚本。
7. **检查交付**：检查文字、隐私、链接、移动端、对比度、键盘操作、动态效果和打印结果，再提供本地预览。

## 内容与隐私要求

- 简历是事实来源，不照搬原有排版。
- 没有证据的数据必须省略、弱化表述或标记为待确认。
- 默认不公开身份证号、详细住址、私人电话、内部文件、客户数据等敏感信息。
- 原始简历、分析笔记和职位匹配报告放在网站公开目录之外。
- 发布到互联网前，先让用户确认公开内容和联系方式。

## 网站质量要求

- 首页应说明“是谁、做过什么、能解决什么问题、如何联系”。
- 项目案例应包含个人角色、问题、行动和有证据的结果或作品。
- 关闭 JavaScript 后，主要内容仍然可以阅读。
- 动态效果服务于信息层级和交互反馈，不遮挡姓名、项目或联系方式。
- 网站需要适配手机，并尊重系统的“减少动态效果”设置。
